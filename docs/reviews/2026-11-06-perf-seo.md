Branch `fix/perf-seo`. Production build (`bun run build`, then `next start` on port 3395) against an isolated compose
stack (`-p receipt-ocr-perfseo`, Postgres 5495, RustFS 9095), fixture OCR, no Gemini calls. Lighthouse 13.6.0 CLI
(installed in a scratch directory with the repo's 7-day cooldown, not added to the repo), mobile form factor,
simulated throttling, 3 runs per page, median. Signed-in pages use a session cookie from a local test account.

Status: fixes, before and after Lighthouse runs and 390/1440 screenshots are done. CI on the final head passes: lint, format, dependency checks, typecheck, unit tests, build, and both e2e jobs including `e2e/seo.spec.ts`. See "Not verified".

How to read these:

- Public pages were already fast on load metrics. Simulated LCP on home stays about 1.21 s; it is set by the shared
  26 KB (gzip) Tailwind stylesheet and the two preloaded fonts, not by page code. The gains here are JS weight,
  accessibility (home 98 to 100, sign-up 96 to 100) and SEO metadata.
- Home LCP element: before, the hero copy faded in from opacity 0 over 0.7 s, so Chrome skipped it and reported the
  header "Get started free" button as LCP. After, the hero text is visible at first paint and is the LCP element.
  Observed (unthrottled) home first paint is unchanged: 95 to 107 ms warm before, 109 to 128 ms after. One cold first
  run before measured 1451 ms; that was server warm-up, not the page, and is not a real gain.
- Simulated LCP on /app, /app/history and the receipt page is bimodal: individual runs land at about 0.8 s or about
  4 s on the same build (for example /app before 772, 3820, 781 ms; after 3840, 3974, 776 ms). The swap between /app
  and /app/history in the medians is noise, not a change; this branch does not touch those pages. Three runs are not
  enough there; use 5 or more, or the observed numbers (LCP 70 to 470 ms).

## Fixed

- Hero and preview use a transform-only entrance (`animate-rise`), so the hero text paints at once and is the LCP
  element (it was the header button). First-paint time itself did not change; see "How to read these".
- Support widget: launcher only on page load; the form, its fields and Turnstile load with `React.lazy` on first open
  (warmed on hover or focus). A draft survives closing.
- FAQ uses native `details`/`summary`: no client JS and every answer is in the HTML.
- SiteHeader and ContactButton resolve button classes on the server; the client islands no longer ship cva,
  tailwind-merge or the Base UI Button.
- Hero floating receipts are server-rendered; only the pointer parallax is a client island.
- Per-page titles, descriptions (50 to 160 chars), canonical, og:url, og:title and Twitter tags via `pageMetadata` in
  `lib/seo.ts`. Before, every page inherited the home page's og:title, og:url and description.
- OG images: privacy and terms have their own; other pages name the root card explicitly (a page-level `openGraph`
  drops the inherited file image).
- JSON-LD on home: Organization, WebSite, SoftwareApplication (free plan offer only, no ratings or reviews) next to the
  existing FAQPage, which matches the visible FAQ.
- robots.txt blocks only `/api/` and the lab prefixes. `/app`, `/admin` and the auth flows are crawlable so crawlers
  can see their noindex; `X-Robots-Tag: noindex` is now also sent on those paths (including the signed-out redirect).
- Sitemap has `lastModified` for the legal pages, from the same dates the pages print.
- A11y: heading-order (product preview h3 after h1), link-in-text-block (sign-up terms links now underlined).
- CI guard: `e2e/seo.spec.ts`.

## Follow-ups for other tracks (not edited here)

- Root layout (PWA track): DM Sans with the `opsz` axis (62 KB) and JetBrains Mono (40 KB) are preloaded on every
  page; consider `preload: false` for mono or dropping the axis. Root `openGraph.url: "/"` and the 179-char
  `siteDescription` are still inherited by pages without their own metadata (404, invitation, /app).
- /app/history (mobile shell track): simulated LCP 4.1 s (observed 388 ms vs FCP 92 ms). The LCP element is the search
  box placeholder, which paints only after the toolbar's JS runs.
- /app/receipts/[id] (mobile shell track): simulated LCP 4.1 s; the LCP element is the receipt image (634 ms render
  delay). The `<img>` has no width and height. A11y: `dl` wraps `dt`/`dd` in extra divs (definition-list, dlitem).

## Lighthouse CI

Not added. It would cost a second production build and server in CI (about 3 to 4 minutes for 4 public pages x 3
runs) plus a pinned `lighthouse` or `@lhci/cli` dev dependency. The simulated numbers above vary too much on app pages
to gate on; a budget on JS bytes per route (from the build manifests) and the `e2e/seo.spec.ts` checks catch the
regressions that matter for less.
