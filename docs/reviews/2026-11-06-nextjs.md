Read-only. Measured with `bun run build` (Turbo cache hit, so no recompile; route table and `.next` chunk sizes read from the cached output). Turbopack in Next 16 prints no First Load JS column, so sizes below are raw (uncompressed) client chunk bytes per route, summed from each route's client-reference manifest.

## P1

None. No correctness or security defect found in the Next.js layer.

## P2

### P2-1. No `loading.tsx` under `/app`; polling `router.refresh()` re-runs the whole layout
- `app/app/` has no `loading.tsx` (only `app/admin/loading.tsx` exists). `app/app/layout.tsx:34-44` awaits session, scope, allowance, usage and plan before streaming anything, and each page (`history/page.tsx:27`, `receipts/[id]/page.tsx:8`) then awaits its own DB reads. Navigation shows no skeleton until the server answers.
- `components/processing-poller.tsx:43,72,96` calls `router.refresh()` while receipts are processing. That re-renders the layout too (session lookup with `disableCookieCache`, usage summary, plan, allowance) on every poll tick, just to update a list. Cost is DB load proportional to polling users.
- Fix: add `app/app/loading.tsx` (reuse the admin skeleton pattern) and `app/app/receipts/[id]/loading.tsx`. For polling, prefer client state: the pollers already fetch `GET /api/receipts/:id`; update the row from that JSON and only call `router.refresh()` once on the transition to completed or failed (list poller at line 96 refreshes unconditionally on a timer, so gate it on a status-change signal).
- Effort: loading files 30 min; poller change 2 to 3 h.

### P2-2. Landing page header pulls the Better Auth client and fires a session fetch for every anonymous visitor
- `components/site-header.tsx:1,14,20` is a `"use client"` component calling `authClient.useSession()` in the static `/` page. Every visitor triggers `/api/auth/get-session` after hydration and ships `better-auth/react` (+ organization/admin plugins from `lib/auth-client.ts:3-4`) in the landing bundle (169 KB raw total).
- Fix: keep the header static and render the CTA as "Sign in / Get started"; swap to "Open app" by a tiny client island that checks the cookie presence (`document.cookie` is HttpOnly for Better Auth, so instead use a cheap `/api/...` HEAD only when a non-HttpOnly hint cookie exists), or just accept signed-in users seeing "Sign in" and redirect from `/sign-in` (already done at `sign-in/page.tsx:21`). Or import `createAuthClient` without plugins for this component.
- Effort: 1 to 2 h. Gain: one fewer request and smaller LCP-critical JS on the only SEO page.

### P2-3. Lab design pages ship in the production build and the landing owns duplicate code
- `app/(lab)/*` is 11 prerendered routes (`/landing-a` ... `/final-paper`), noindex via `(lab)/layout.tsx:4-6` but publicly reachable, and `components/marketing` + `v2` is about 41% of TS (STATUS.md). They add build time, route-manifest size and crawl surface (robots.ts does not disallow them; only the meta robots tag protects them, which is fine for Google but they still get fetched).
- Fix (when the owner decides on classic as homepage): delete. Until then, gate with `notFound()` in `(lab)/layout.tsx` when `process.env.VERCEL_ENV === "production"` (or `NEXT_PUBLIC_LAB !== "1"`), and add `/final-`/`/landing-` to robots disallow. Note the route group `(lab)` does not appear in the URL, so these paths sit at the root namespace.
- Effort: gate 15 min; delete 1 h.

### P2-4. Admin settings save revalidates the right pages but through two mechanisms and a fragile page list
- `lib/plan-limits.ts:36-50` hand-lists `PLAN_COPY_PAGES` for `revalidatePath`, while `/terms` and `/forgot-password` use `export const revalidate = 3600` and call `getPlanTable()` (an uncached DB read at build and ISR time). Adding another page that prints plan limits and forgetting the list leaves it stale up to 1h; `/sign-in`, `/sign-up`, `/reset-password` are listed but are dynamic (searchParams), so those `revalidatePath` calls are no-ops.
- `saveOcrAction` (`admin/actions.ts:453-457`) only revalidates `/admin` layout. If OCR chain is read elsewhere only at request time that is fine; confirm nothing caches it.
- Fix (small): wrap `getPlanTable` in `unstable_cache`/`fetch`-free tag: `unstable_cache(fn, ["plans"], { tags: ["plans"], revalidate: 3600 })` and `revalidateTag("plans")` in `savePlansAction`. Single source of truth, drops the page list. Longer term, with `cacheComponents: true`, use `"use cache"` + `cacheTag("plans")` + `updateTag("plans")` (read-your-writes for the admin who just saved). Drop the dead entries for dynamic routes now.
- Effort: 1 h now; 0.5 to 1 day for a cacheComponents migration (see P3-1).

### P2-5. Route handler/validation consistency
- Handlers are thin and use `runRoute`/`jsonError` well. Gap: `PATCH /api/receipts/[id]` hand-validates fields with ad hoc `decimal`/`text` helpers (`route.ts:38-52`) while server actions use zod (`admin/actions.ts` uses `z.object`). Two validation styles; the receipt PATCH body is the largest user-controlled JSON surface. Move to a zod schema in `packages/core` (matches the "workflows in core" rule) and return `InvalidInput` for unknown/malformed fields instead of silently ignoring (`decimal` returns `undefined` on a non-finite number, so a bad value is dropped with a 200).
- Effort: 2 to 3 h.

## P3

### P3-1. `cacheComponents` is off; app uses legacy route-segment config
- `next.config.ts` has no `cacheComponents`. Legacy `export const revalidate = 3600` (terms, forgot-password) and `export const dynamic = "force-dynamic"` (`admin/layout.tsx:13`) are used. Both are fine in Next 16 without Cache Components. The `force-dynamic` on admin is redundant (the layout reads cookies/headers via `requireAdmin`) but the comment about "build without auth env" is a valid belt-and-braces; keep or replace with `await connection()`.
- Opportunity if you enable it: `/` static shell + `/terms`/`/privacy` as `"use cache"` with `cacheLife("hours")` and `cacheTag("plans")`; `/sign-in` would need `<Suspense>` around the searchParams/session read. Not needed now; revisit when adding the usage screens (Track 3), where a cached per-workspace rollup with `cacheTag(`usage-${orgId}`)` + `updateTag` after an upload would remove repeated aggregate queries from the layout.
- Effort: spike 0.5 day.

### P3-2. No `app/global-error.tsx`
- Build emitted Next's default `_global-error`. Root layout/`not-found` failures show the unstyled default. `app/app/error.tsx` and `app/admin/error.tsx` exist and are good; there is no `app/error.tsx` for the public pages (sign-in, terms, accept-invitation) and no `app/app/receipts/[id]/not-found.tsx` (the `notFound()` at `receipts/[id]/page.tsx:9` falls to the root 404 which renders the marketing header, inside the app shell it looks like a different site).
- Fix: add `app/error.tsx`, `app/global-error.tsx` (own `<html><body>`), and `app/app/not-found.tsx`.
- Effort: 1 h.

### P3-3. SEO details
- Good: `metadataBase`, canonical via `canonicalFor`, robots/sitemap generated, OG image, JSON-LD on classic landing, noindex on private/lab routes.
- Gaps: `sitemap.ts` has no `lastModified`; `/` landing at `app/page.tsx` has no JSON-LD (the classic lab page has `json-ld.tsx` and `faq`/`landing-page.tsx` reference it; verify `/` actually emits it via `landing-page.tsx`). `robots.ts` does not disallow lab paths (see P2-3). `sign-in` is noindex but `sign-up` only `follow`-ish, fine. Open Graph `url: "/"` in root layout is inherited by every page that doesn't override `openGraph` (terms, privacy get the homepage URL as `og:url`); set per-page `openGraph.url` or drop the root one.
- Effort: 1 h.

### P3-4. Images
- Three raw `<img>` uses, each with an eslint-disable: `user-menu.tsx:30` (OAuth avatar, 32px), `upload-panel.tsx:424` (blob: preview, correct to keep), `receipt-result.tsx:188` (presigned storage URL, changes per request, correct to keep, optimizing it would route private receipts through the image optimizer and cache them). Only the avatar could use `next/image`, needing `images.remotePatterns` for Google/GitHub avatar hosts; the gain is negligible. Add `loading="lazy"`/`decoding="async"` and `width/height` to the receipt image to avoid layout shift. No `images` config in next.config.ts, which is consistent.
- Effort: 15 min.

### P3-5. Fonts
- Root layout uses `next/font/google` for DM Sans and JetBrains Mono with `display: "swap"` and CSS variables: correct and self-hosted at build. Lab-only `fonts.ts` files (`marketing/v2/d`, `final-paper`) add more font downloads only on those routes; goes away with P2-3. JetBrains Mono is used on most data screens so preload is right; consider `preload: false` on mono for the landing if it is not above the fold.

### P3-6. Client/server boundaries
- 47 files carry `"use client"`; placement looks leaf-ward overall (forms, pollers, nav). Candidates to push down: `site-header.tsx` is wholly client for scroll/menu state (see P2-2); `components/auth/*` forms are client by necessity. `lib/*` server modules consistently `import "server-only"` (session, env, http, quota, receipts, plan-limits, runtime): good. `lib/site.ts`, `lib/plans.ts`, `lib/format.ts` are shared and correctly free of secrets. Props crossing the boundary are plain objects (e.g. `MenuUser`, `Usage`), no functions or class instances found.
- `lib/env.ts` is `server-only` yet `app/forgot-password/page.tsx:4` imports `authEnabled` from it: server component, OK.

### P3-7. proxy.ts and instrumentation
- `proxy.ts` is correct Next 16 form (default export `proxy`, matcher limited to /app and /admin, optimistic cookie check only, real check in layouts and `requireAdmin`). It strips and re-sets the `REQUESTED_PATH_HEADER` so a client cannot spoof it: well done. Minor: matcher lists `"/app/:path*", "/app"` redundantly (`/app/:path*` already matches `/app`).
- `instrumentation.ts` gates on `NEXT_RUNTIME === "nodejs"` and dynamically imports the env check, fail-fast on misconfig: good. When the observability track lands (Axiom/Sentry), add `onRequestError` here; Next reports render errors through it, and `app/app/error.tsx` currently logs with `console.error` from the client only (`error.tsx:21`), which never reaches server logs, so server-side render failures have only Next's default log line plus digest.
- Effort: 0.5 h for the matcher; observability is its own track.

### P3-8. `after()` usage
- `api/receipts/route.ts:81` and `retry/route.ts:38` use `after()` correctly for queued extraction; `maxDuration = 60` covers the work. On Vercel, `after` work shares the function's `maxDuration`, so a queued extraction that exceeds the remaining budget is killed silently; the 50 s OCR deadline in the comment fits. Worth a note in docs that queued mode is not a real background job until BullMQ lands.

### P3-9. Security headers / CSP
- Headers set in `next.config.ts` (HSTS, nosniff, frame deny, referrer, permissions) are good; CSP is report-only with `'unsafe-inline'`, and the comment explains why. Since proxy.ts exists, a per-request nonce CSP could be added there later, but it forces all pages dynamic (conflicts with the static landing); keep report-only or use hash-based CSP. `Content-Security-Policy-Report-Only` has no `report-to`/`report-uri`, so violations are never collected; add one before relying on it.

## Done well

- Async request APIs everywhere (`await params`, `await searchParams`, `await headers()`); no sync access.
- `react.cache` dedupes `getSession`/`getActiveScope`/`getCurrentPlan` per request; layout fetches in `Promise.all`.
- Route handlers are thin adapters over `runRoute`/`runBackground` with typed error to status mapping, public vs internal messages, cross-origin check on mutations, `Cache-Control: no-store` on export.
- `server-only` on all privileged lib modules; env parsed centrally with build-phase awareness.
- File conventions: error boundaries for /app and /admin, admin `loading.tsx`, root `not-found` with metadata, `(lab)` route group with noindex layout, `manifest.ts`, `icon.svg`, `opengraph-image.tsx` via `next/og`.
- `metadataBase` + `canonicalFor` that omits wrong localhost canonicals; robots/sitemap guard on missing site URL.
- `next/font` self-hosting; no `<link>` font tags; CSS imported, not linked.
- `outputFileTracingRoot` + `transpilePackages` set for the monorepo; standalone output gated by env for Docker, ignored on Vercel.
- Static where possible (`/`, legal pages with ISR + explicit revalidation after admin save).
