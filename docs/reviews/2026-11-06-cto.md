## 2. Can the architecture take the owner's direction?

**The boundaries are mostly right.** `packages/ai` makes one call to one model and classifies the error
(`errors.ts:32-62`) with AI SDK types, not Gemini types. `packages/core` owns routing (`ocr.ts:64-103`: one shared
deadline, fallback by failure kind). `Settings` caches the admin chain for 30 s (`settings.ts:167`). Since #22,
`extractStored` takes only an id (`pipeline.ts:62`), so a worker could already call it. The direction fits these layers.
What breaks it is data that gets dropped, plus Google assumptions left in core.

**Usage is captured, then dropped.** `extractReceipt` returns only input, output and total tokens
(`extract.ts:27-31,105-111`). The installed `ai@7.0.154` also exposes `inputTokenDetails.cacheReadTokens` and
`outputTokenDetails.reasoningTokens` (`ai/dist/index.d.ts:344-382`). `repo.complete` stores `model` but no usage
(`repository.ts:226-232,300-321`). The usage reaches a log line only on the instant path (`api/receipts/route.ts:132`).
The queued and retry paths don't log it at all (`recordOcr`, `lib/http.ts:105-111`). Failed attempts lose their tokens:
`StepFailure` has no usage (`ocr.ts:51,93-94`), although `NoObjectGeneratedError` carries `.usage`
(`ai/dist/index.d.ts:8293`). Each attempt has latency (`OcrAttempt.ms`) but no cost.

**Google is hard-coded in five places:** `models.ts:7` (provider union), `extract.ts:59-63` (registry),
`ocr.ts:105-108,136` (`keys = { google }`), `settings.ts:74-80` (`providerAvailability`), `settings.ts:63-101`
(`GEMINI_MODEL` default chain). Models also lack capability data. HEIC is accepted (`files.ts:6-13`). To my knowledge
OpenAI and Anthropic vision take only JPEG, PNG, GIF and WebP (check their docs before relying on this). With those
providers as fallbacks, a HEIC upload would fail as `bad-image`, and `bad-image` ends the chain (`ocr.ts:31-36`).

**Where usage capture and telemetry should go:**
- `packages/ai`: return one normalized call record (`{ model, usage: {input, cachedInput, output, reasoning},
  latencyMs, finishReason }`) on success, and attach it to the thrown error on failure. No telemetry SDKs here.
- `packages/core`: `runChain` puts each call's usage and cost on its `OcrAttempt`. `ReceiptRepo.complete`/`fail` write
  all attempts **in the same transaction** they already open. Usage is business data stored in the DB, not telemetry.
  The worker inherits this unchanged.
- `apps/web`: `lib/log.ts:15-27` stays the single sink. Axiom needs no code (Vercel log drain or integration reading
  stdout JSON). PostHog and Sentry live behind env checks with dynamic `import()`, server-side only. Core never imports
  them.

**Overbuilt or dead:** `app/(lab)` holds 11 static design-direction routes (`(lab)/layout.tsx:3` says "Temporary"). They
pull in `components/marketing` (93 files, 14,584 lines, nothing imports them outside `(lab)`), about 41% of all TS/TSX
lines. `user_credentials` and `receipts.storage_source` are never read or written (`db/src/index.ts:82,123-145`;
the only other hit is a CSV test fixture). `RetryClaim.imageObjectKey` has been unused since #22
(`repository.ts:105-106,375-376`; `pipeline.ts:118-131`). Two upload modes remain, with two branches in one route
(`route.ts:72-139`). `bench/ocr.ts:39-60` monkeypatches `fetch` to read Gemini's `usageMetadata`, but
`extractReceipt` now returns usage.

**Duplicated rule:** `lib/receipt-permissions.ts:6-14` re-implements `canManageAnyReceipt` plus `writable`
(`repository.ts:41-43,150-153`). They agree today and will drift.

## 3. Hot path cost (measured; local Postgres, warm unless noted)

| Operation | SQL stmts | Round trips | Other |
|---|---|---|---|
| `getSession` (Better Auth, `disableCookieCache`, `session.ts:18-20`) | 1-2 (source: `findOne` session `join: { user }`) | 1-2 | not measured |
| `resolveScope` (`getActiveScope`) | 1 | 1 | |
| `userPlan` | 1 (cold: +1 settings load, +1 `pg_type` on first connect) | 1 | settings cached 30 s |
| `checkQuota` | 1 | 1 | |
| `Ocr.ready` | 0 | 0 | |
| `ingestUpload` | 1 insert | 1 | S3 PUT |
| `extractStored` | 6 (get with items, BEGIN, UPDATE, DELETE items, INSERT items, COMMIT) | 5 | S3 GET of the same bytes, model call(s) |
| Poll `GET /api/receipts/:id` | 1 (+ session + scope) | 3 | loads items + `raw_json` to return a status |
| Detail page | 1 + layout (session, scope, allowance, plan, quota) | about 6-7 | presign is local |
| History page | 2 + layout | about 7-8 | |

**One instant upload costs about 12-13 statements and 10-11 sequential round trips, 2 S3 calls (PUT, then GET of the
bytes the route already holds, `route.ts:64` → `pipeline.ts:79`) and 1+ model calls.** Session → scope is serial, and
so is plan → quota (`lib/quota.ts:12-15`). Then `router.push` (`upload-panel.tsx:188`) renders the detail page for about
6-7 more. Locally all DB work takes under 30 ms. In production the cost is round trips × Vercel↔Supabase latency, so
co-locating the regions matters more than any code change (not verified which regions are used).

**What the direction adds:** an `ocr_calls` multi-row INSERT inside the existing complete/fail transaction is +1
statement and +1 round trip per extraction. Computing cost costs nothing extra if prices live in `models.ts`. Telemetry
costs nothing when unset if loaded lazily. When set, a PostHog capture is batched and flushed in `after()`, so it stays
off the response path.

**Cheap trims:** merge `userPlan` and the usage count into one query (−1 RT). `extractStored` and the poll endpoint
use a narrow `select` instead of `findFirst({ with: { items } })` (`repository.ts:387-398`). The instant path could
pass the bytes it holds so the S3 GET is skipped (keep reading by id for workers). The admin overview runs 5 awaits in
sequence (`admin-queries.ts:84-135`); run them with `Promise.all`.

**Bundle (first-load JS, gzip, framework 130 KB included, deduped):** `/app` 252 KB, `/app/receipts/[id]` 264 KB,
`/admin/settings` 257 KB, `/landing-e` 169 KB. Route-only: `/sign-in` 51 KB, `/app/history` 131 KB. The largest app
chunk is the Better Auth client plus nanostores (15.4 KB). A client-side Sentry or PostHog SDK would add to every page.
Keep both server-only until a reason appears.

## 4. Findings

### P0

**P0-1 Deleting receipts gets around both the daily quota and `OCR_DAILY_CAP`.** `usage` counts rows in `receipts`
(`repository.ts:490-516`), and `remove` hard-deletes them (`repository.ts:467-475`). A free user (20/day, 10/min,
`plans.ts:24`) owns their personal workspace, so they can delete and re-upload, up to 10/min ≈ 14,400 paid OCR calls a
day. The global cap counts the same rows. Not exercised end to end. The rule follows from the code, and no test covers
deletion against quota (`receipts.int.test.ts` has none).
*Fix:* add an append-only `ocr_calls` ledger (P0-2) and count quota and the cap from it. Set the receipt FK to
`on delete set null` so usage outlives the receipt.

**P0-2 Usage and cost are dropped on every path** (§2 evidence). This blocks direction item 1 and leaves spend unknown.
*Fix:* one migration adds `ocr_calls(id, receipt_id → set null, organization_id, user_id, attempt, step, provider, model,
outcome, input_tokens, cached_input_tokens, output_tokens, reasoning_tokens, cost_micros bigint, price_version,
latency_ms, created_at)` with indexes `(organization_id, created_at)`, `(user_id, created_at)` and `(created_at)`.
Write it in the complete/fail transaction, failures included. Customer view: the month's tokens and cost per workspace,
plus the attempts on the receipt detail page. Admin: by model and day. Store cost when the call is written, so a later
price change doesn't rewrite history.

### P1

**P1-1 Generalize the provider plumbing before adding providers.** Drive availability and keys from
`OCR_PROVIDERS[].keyEnv` in one loop, and let `packages/ai` read its own key env vars. Drop `keys` from core and keep it
only as the future BYOK hook. Add to each `OcrModel`: `mediaTypes`, `pdf`, `providerOptions` (thinking/reasoning
budget, since reasoning tokens bill as output) and `price {input, cachedInput, output, updated}`. Then
`activeChain(routing, available, mediaType)` skips models that can't read the file. **On the direction:** "most widely
used vision models" is the wrong goal. Every model costs an allowlist entry, a price, a capability row and a benchmark
run. Aim for 3 providers and 4-6 models, each one admitted by the benchmark. An alternative is the Vercel AI Gateway:
the installed `ai` already exports `createGateway`, so there are no new deps and one key. Its pricing, cost reporting
and data terms are unverified.

**P1-2 Make the gate binding.** Protect `main` and require the three CI jobs. On 11-06, six PRs merged within 32
minutes (04:17-04:49), and #20 merged 2 minutes after its first `format:check` failure (it passed on re-run). The
production deploy already waits for CI (`production.yml` `workflow_run` + `conclusion == 'success'`).

**P1-3 Make the benchmark real before a second provider ships.** It needs 30+ real, PII-stripped receipts, prices moved
into `models.ts` (delete `bench/prices.json`), the fetch monkeypatch replaced with the returned usage, and committed
per-model summaries (accuracy, p50/p95, schema-failure rate, cost per receipt). Run `--resize 1600` to decide
client-side downscaling: `upload-panel.tsx` has no resize, and 10 MB photos go straight to the model.

**P1-4 Delete the lab** (`app/(lab)`, `components/marketing`) once the owner has picked a landing page. Keep only the
chosen one under `components/`. That removes 14.6k lines, 11 build routes, and a lot of knip, lint and review surface.

**P1-5 Make observability opt-in, built on the existing wide event.** Axiom: config only. Sentry: server-side only,
`onRequestError` plus a `register()` in `instrumentation.ts` that imports the SDK only if `SENTRY_DSN` is set; no client
SDK or build plugin yet. PostHog: `posthog-node` imported lazily in `lib/log.ts`, forwarding `receipt.*` events,
including AI generations built from the same `OcrAttempt` records, flushed in `after()`. Skip OTel and
`experimental_telemetry` unless traces are actually wanted.

### P2

- **P2-1** Drop `user_credentials` and `receipts.storage_source` in one migration; keep `docs/byok-key-management.md`.
- **P2-2** Move `canEditReceipt` into core as a plain function, used by both `writable()` and the receipt page; delete
  `lib/receipt-permissions.ts`.
- **P2-3** Apply the hot-path trims from §3: merged plan+quota query, narrow selects for poll and `extractStored`, an
  optional bytes hand-off on the instant path, `Promise.all` in the admin overview.
- **P2-4** The client accepts no PDFs (`upload-panel.tsx:28,61` checks `image/*`) but the server does (`files.ts:12`),
  so one of the two is wrong. Decide which, together with the per-model `pdf` capability.
- **P2-5** Remove `RetryClaim.imageObjectKey` and the fetch monkeypatch in `bench/ocr.ts`.
- **P2-6** Collapse instant and queued into queued + poll (one route branch, one wide event, the same path a worker
  uses). The detail page already polls (`processing-poller.tsx:8-10`).
- **P2-7** A DB error during the settings load caches the env-default chain for 30 s (`settings.ts:159-167`). With
  several providers, that default may have no key, so uploads return 503 for 30 s. Keep the last good snapshot instead.

## 5. Is it time for a worker? Not yet.

The synchronous path fits: 50 s chain deadline under `maxDuration = 60` (`ocr.ts:18`, `route.ts:24`). Queued uploads
and retries run in `after()`. A stale `processing` receipt reads as failed and can be retried
(`repository.ts:117-139`). Writes are guarded by attempt (#22). Redis would add infra, cost and a second deploy target
for a few users. **Triggers to revisit:** stale/killed background rate above about 1% (count from
`receipt.extract.background` events), batch uploads of 10+ files, multi-page PDFs, or using provider batch APIs for
cheaper bulk OCR. When one of these fires, start with a Postgres claim loop (`status = 'uploaded'` with
`FOR UPDATE SKIP LOCKED`, calling `extractStored` by id) before BullMQ. AGENTS.md names BullMQ, so the owner should
make that choice explicitly.

## 7. CI/CD and supply chain

Healthy. Actions are pinned to full SHAs. Postgres, RustFS and `oven/bun` images are pinned by digest
(`docker-compose.yml:19,39,58`, `docker/Dockerfile.*`). The 7-day cooldown is set in `bunfig.toml` and on all five
Dependabot ecosystems. `check:deps`, `knip`, `audit` run in `static`. Integration tests and Playwright run against
service containers, and production deploys only after CI passes on a push. The one gap is the missing branch
protection (P1-2). Every provider or telemetry SDK added (`@ai-sdk/openai`, `@ai-sdk/anthropic`, `posthog-node`,
`@sentry/nextjs`) is new third-party code under the 7-day rule. That is a reason to prefer fewer providers, or the
gateway.
