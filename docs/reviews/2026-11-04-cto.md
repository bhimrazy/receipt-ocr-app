## 1. Architecture

**Boundaries.** `db`, `storage`, `ai`, `email`, `ui` are small and each has one job; they earn their keep because a
future `apps/worker` reuses them. Don't add more packages. Two leaks:

- `packages/ai` is not a provider boundary: the only export is `extractReceiptWithGemini` (`packages/ai/src/index.ts:74`),
  and `AppConfig` carries `geminiApiKey`/`geminiModel` (`packages/core/src/index.ts:22-28`). AGENTS.md forbids this.
  Fix: `extractReceipt({ model: "google:gemini-…", … })` via the AI SDK provider registry, returning `{ extraction, usage }`.
  That is also what the benchmark needs (section 4).
- Two schemas for one shape: Effect `Schema` (`ai/src/index.ts:9-28`) and zod (`:53-72`), decoded twice (`:118`).
  `Output.object` already validates with zod. Drop the Effect schema and derive the type with `z.infer`.

**Effect in `packages/core`.** 546 lines, of which roughly two thirds is `Context.Tag`/`Layer`/`Effect.tryPromise`
wrapping (`core/src/index.ts:53-189, 220-258, 267-411`). The real value is small: typed failure tags and step timings.
The cost shows up in every route: `Effect.runPromiseExit(... Effect.provide(AppLive))` plus `failureContext` glue
(`api/receipts/route.ts:11-39, 119-124, 151-161, 184-189`; `[id]/route.ts:14-19, 96-101, 117-122`; `export/route.ts:19-24`).
Verdict: ceremony for CRUD, acceptable for the two-stage pipeline. Simplification, in order of value:

1. Keep Effect only for `ingestUpload` / `extractStored`. Make reads and edits (`getReceipt`, `listReceipts`,
   `updateReceipt`, `deleteReceipt`) plain async functions over Drizzle, called directly from pages and routes.
2. Build the runtime once (`ManagedRuntime.make(AppLive)` at module scope) instead of `Effect.provide(AppLive)` per
   call, which rebuilds every layer each time (the reason `createDb` had to grow a memo, `db/src/index.ts:140-150`).
3. `ConfigLive` requires the Gemini key for *every* program (`core/src/index.ts:205`), so History and the receipt page
   fail when only OCR is unconfigured. `requireEnv` also `throw`s inside `Effect.sync` (`:191-197, 201`), turning the
   typed `ConfigError` into a defect. Split config per service or fail lazily.

If the owner prefers zero Effect: a `processReceipt(deps, input)` function with a `deps` object is equally reusable
by a worker and removes the dependency. Either way, stop it spreading.

**Route handlers** are mostly thin. `POST /api/receipts` is 229 lines because of wide-event bookkeeping and two
inlined modes; move the `after()` body to a `runBackgroundExtraction()` helper.

**Underbuilt (correctness / security / data loss):**

| # | Finding | Evidence | Fix |
|---|---|---|---|
| U1 | Deleting a receipt (or a workspace via cascade) never deletes the S3 object: orphaned images, privacy gap | `core/src/index.ts:379-389`, `db/src/index.ts:45` | delete object after row; nightly orphan sweep later |
| U2 | Queued receipts can stick in `processing` forever if the function is killed during `after()`; no sweeper, no `maxDuration` | `api/receipts/route.ts:142-176` | export `maxDuration`; on read, treat `processing` older than N min as failed |
| U3 | MIME trusted from the client, any `image/*` accepted (SVG included) and stored with that Content-Type | `api/receipts/route.ts:114`, `core/src/index.ts:447` | allowlist jpeg/png/webp/heic + magic-byte check |
| U4 | Signup hook inserts org then member without a transaction; a failure leaves a user with no workspace (409 on upload) | `lib/auth.ts:118-135` | wrap in `db.transaction` |
| U5 | Quota is check-then-insert, so parallel requests overshoot; per user, not per workspace; no global spend ceiling while email verification is optional | `lib/quota.ts:26-65`, `lib/auth.ts:59-68` | accept the race for now, add a global daily OCR cap env |
| U6 | Sidebar usage meter is hard-coded "23 / 50 this month" | `app/app/layout.tsx:51-60` | render real `checkUploadQuota` numbers or remove |
| U7 | History search/category filter only filters the current page of 25 | `components/history-table.tsx:47-55` | push `q`/`category` into the query (searchParams) |
| U8 | `/api/contact` has no rate limit and logs the email + message body into logs | `api/contact/route.ts:64-65` | rate-limit by IP; log length only |
| U9 | Rate-limit IP from `x-forwarded-for` is spoofable when self-hosted without a trusted proxy | `lib/auth.ts:91-94` | fine on Vercel; document for Docker |

**Overbuilt for an MVP:** the Effect service layer (above); the unused `user_credentials` table and `storageSource`
column for BYOK that has no code path (`db/src/index.ts:62, 92-109`) — fine to keep, but don't build on it until BYOK
is scheduled; the two upload modes (instant + queued) — keep queued only and let instant be "queued + poll fast" once
U2 is solved.

## 2. Performance

**Upload path** (`ingestUpload` → `extractStored`): db.create → storage.put → db.markProcessing → ai.extract →
db.complete (tx) → db.load. Gemini dominates (seconds; capped at 45 s, `ai/src/index.ts:50`). Fixes in order:

1. **Downscale before OCR.** A 10 MB phone photo goes to Gemini as-is (`route.ts:9,110`). Resize client-side to
   ~1600 px long edge, JPEG/WebP q≈0.8 (canvas or `createImageBitmap` in `upload-panel.tsx` before line 61).
   Cuts upload time, storage, token cost and OCR latency together. Measure accuracy with the benchmark first.
2. **New `S3Client` per call** (`storage/src/index.ts:39, 59`) loses keep-alive/TLS reuse for every put and every
   signed URL. Memoize per config like `createDb`.
3. Run `storage.put` in parallel with nothing waiting on it: the row insert must come first (id), but
   `db.markProcessing` could be folded into `db.complete` to save a round trip. `db.load` after `db.complete` is a
   second read that could return from the transaction.
4. The quota query and `getActiveScope` run serially before `formData()` (`route.ts:52-92`); start
   `request.formData()` early (`async-api-routes`).

**DB.** `postgres-js` with `prepare:false`, `max: 5`, idle 20 s, memoized per URL (`db/src/index.ts:150-169`) is right
for Supabase's transaction pooler. On Vercel set `DATABASE_POOL_MAX=1-2` (many instances × 5 adds up at the pooler).
Missing indexes:

- **`receipt_items.receipt_id` has no index** (no `CREATE INDEX` for it in `apps/web/drizzle/*.sql`). Every
  `with: { items: true }` and every cascade delete scans `receipt_items`. Add `index("receipt_items_receipt_id_idx")`.
- Quota counts by `user_id` with a `created_at` filter, served only by `receipts_user_id_idx`; make it
  `(user_id, created_at)` (`db/src/index.ts:69`).

No N+1: the relational query loads items in one statement. But History loads items for 25 rows
(`core/src/index.ts:366-372`) and ships them plus `rawJson` across the RSC boundary to a client component that uses
neither (`components/history-table.tsx`; `server-serialization`). Add a `listReceiptSummaries` that selects only the
table columns. Export loads up to 5 000 receipts with items into memory and builds the CSV in one string, despite the
"Streamed" comment (`export/route.ts:8-37`); fine at MVP volume, correct the comment or stream by pages.

**RSC / bundle / caching.** `getSession` is not wrapped in `React.cache` (`lib/session.ts:11-14`), so layout and page
each call it (`lib/workspaces.ts:18`, `lib/receipts.ts:55`); cookie cache makes this cheap, but wrap it anyway
(`server-cache-react`). The app shell's client components refetch the session the server already had
(`workspace-switcher.tsx:19-21`, `impersonation-banner.tsx:15`, `admin-link.tsx:19`); pass the server session as a
prop. Receipt preview uses `<img>` with a 10-minute presigned URL (`receipt-result.tsx:55`, `storage/src/index.ts:57`):
acceptable — `next/image` gains little for a one-off private signed image. Landing page is static; nothing to cache on
`/app/*` beyond that. No heavy client deps spotted (lucide per-icon imports are fine).

## 3. Testing strategy (lean version of mohar)

What mohar does that matters here: one runner script instead of hand-picked dirs (`scripts/test.sh`), real
PostgreSQL in CI next to the fast suite, Playwright for browser checks (`scripts/screenshot.mjs`), probes from reviews
become tests named after the behaviour (`docs/handoff/review-rules.md`, "Probes become tests"), and actions pinned to
SHAs (`.github/workflows/ci.yml:75`). What to skip: sharding, heavy.sh slots, merge queues, changelog fragments.

**Today:** 30 Vitest cases over pure helpers (`apps/web/lib/{csv,format,plans,quota,redirect}.test.ts`,
`packages/ai/src/categories.test.ts`). `quota.test.ts` only covers `quotaMessage`; nothing covers the pipeline,
scoping, or routes.

**Layers and first tests:**

1. **Unit (Vitest, existing).** Add `packages/core/src/processing.test.ts`: `extractStored` marks the receipt failed
   on AI error; `ingestUpload` rejects non-images. Use in-memory fakes for the three services (this is the one place
   Effect layers pay off). `packages/ai/src/extract.test.ts`: decode of a recorded provider response.
2. **Integration (`*.int.test.ts`, real Postgres + S3).** `vitest.int.config.mts`, `pnpm test:int`. Use the compose
   Postgres on 5433 (a fresh database per run, migrate with drizzle-kit) and RustFS for S3. First tests:
   `receipts.int.test.ts` — workspace isolation (org B cannot get/update/delete org A's receipt via `scopeWhere`);
   delete cascades items (and, after U1, the object); `quota.int.test.ts` — minute/day windows against real rows;
   `storage.int.test.ts` — put + presigned GET round-trip against RustFS. OCR stubbed by a fixture-replay provider.
3. **E2E smoke (Playwright, `apps/web/e2e/`).** One spec per flow, run against `next build && next start` with
   `OCR_PROVIDER=fixture` so it is deterministic and free: `auth.spec.ts` (sign up → lands in workspace),
   `upload.spec.ts` (upload fixture → result shows merchant/total), `history.spec.ts` (row present, pagination),
   `export.spec.ts` (CSV download has the row). Pin `@playwright/test` in devDependencies (no global install).
4. **Screenshot QA.** `scripts/screenshot.mjs` ported from mohar but using the local `playwright` dependency and
   Better Auth's `/sign-in` form; widths 1440 and 390, dark default. Used in PR bodies, not as a pixel-diff gate.

**Scripts:** `test` (unit), `test:int`, `test:e2e`, and `scripts/test.sh` that brings up `docker compose up -d
postgres rustfs`, migrates, and runs all three.

## 4. Benchmarking

**Fixtures:** none exist (no images tracked in the repo). Needed: `bench/fixtures/<id>.jpg` + `<id>.json`
ground truth, 30–50 receipts covering the failure classes already seen — locale separators (IDR `31.000`,
`ai/src/index.ts:100-103`), EUR comma decimals, faded thermal, skewed phone shots, long receipts (30+ lines), tips,
multi-currency, handwritten totals. Use own receipts or a permissively licensed public set (check licence before
committing); strip PII.

**`pnpm bench:ocr`** → `bench/ocr.ts` (runs with `tsx`), calling `packages/ai` `extractReceipt` per
`--models google:gemini-3.7-flash,…` with concurrency 2:

- Field accuracy: exact match on `currency`, `receiptDate`, `category`; numeric match within ±0.01 on `total`, `tax`,
  `subtotal`; `merchant` normalized fuzzy match; items F1 by name similarity + price match.
- Latency p50/p95 per model, cold vs warm; schema-failure and timeout rate.
- Cost: `usage.inputTokens/outputTokens` × a price table in `bench/prices.json` (dated, edited by hand).
- Output `bench/results/<date>-<model>.json` plus a markdown table; commit summaries, gitignore raw output.
- Variant flag `--resize 1600` to decide recommendation 2.1 with data.

**Upload load test:** `loadtest/upload.k6.js` (k6 binary, not npm), against the local stack with the fixture OCR
provider so it measures our path, not Gemini: ramp 1 → 20 VUs, POST `/api/receipts?mode=queued` with a 1–3 MB image.
Report p95 of ingest, error rate, Postgres connections (`pg_stat_activity`) to validate the pool settings. One
command: `pnpm bench:load` (requires k6 installed; ask before installing).

## 5. CI/CD

**Preview failure is a credential, not the workflow.** Run 32592383316 log: `Retrieving project…` then
`Error: The token provided via --token argument is not valid.` `VERCEL_TOKEN` was set on 2026-06-20 at repo level and
in both `vercel-preview` and `vercel-production` environments; production last succeeded 2026-06-20. The token has
since expired or been revoked. Fix: create a new Vercel token scoped to the team, update `VERCEL_TOKEN` in the
`vercel-preview` **and** `vercel-production` environments (environment secrets win over repo secrets), delete the
stale repo-level copies. Production will fail the same way on the next merge to main. Also:

- Dependabot PRs get no secrets, so previews always fail for them (run 28765782595): add
  `if: github.actor != 'dependabot[bot]'`.
- Pass the token as `env: VERCEL_TOKEN` rather than `--token=` on the command line.
- Simplest option: drop both workflows and use Vercel's Git integration (previews + PR comments built in).

**Pinning (owner policy):** unpinned — `actions/checkout@v4`, `pnpm/action-setup@v4`, `actions/setup-node@v4`,
`peter-evans/find-comment@v3`, `peter-evans/create-or-update-comment@v4` (`preview.yml`, `production.yml`), plus
`npm install -g vercel@latest` (no cooldown, runs unvetted code) and `minio/minio:latest`, `minio/mc:latest` in
`docker-compose.yml:35,53`. Pin to full SHAs (mohar's `ci.yml` has current SHAs for checkout/setup-node), pin
`vercel@<exact>`, pin images by digest (and swap MinIO for RustFS as planned). Node 20 in CI vs `node:22-alpine` in
the Dockerfile — use 22 everywhere. Cooldowns are 2 days (`pnpm-workspace.yaml:4` `minimumReleaseAge: 2880`,
`dependabot.yml` `default-days: 2`) vs the 7-day policy; Dependabot has no `github-actions` ecosystem entry.

**Missing gate:** no workflow runs typecheck or tests. Add `.github/workflows/ci.yml`: `pnpm install --frozen-lockfile`
→ `pnpm typecheck` → `pnpm test` → `pnpm test:int` (Postgres service + RustFS container) → `pnpm build`; e2e smoke
as a second job on PRs to main. Make it the required check; deploys depend on it.
