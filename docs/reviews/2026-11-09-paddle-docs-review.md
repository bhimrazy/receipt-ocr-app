# Paddle docs review (2026-11-09)

_Review · docs only, no billing code changed_

Production checkout failed with `transaction_default_checkout_url_not_set` ("Cannot create a transaction or open a
checkout as no default payment link has been set for this account"). Our setup guide never named that setting, and an
earlier check used `POST /transactions/preview`, which doesn't need it. This review reads Paddle Billing's own docs
against our integration to find everything else of that kind.

Sources were read on 2026-11-09 from developer.paddle.com (through its `llms-full.txt` and the `.md` copies of each
page), paddle.com/help and paddle.com/pricing. No Paddle API was called. The code read: `packages/core/src/billing/`,
`apps/web/app/app/settings/billing/`, `apps/web/components/billing/`, `apps/web/lib/csp.ts`, `apps/web/lib/pricing.ts`,
`/pricing`, `/refunds` and `/terms`.

Fixed in this PR: [production-environment.md §10](../production-environment.md#paddle-account-settings) (new
"Paddle account settings" step list; 10a to 10c corrected), [testing-payments.md](../testing-payments.md#if-somethings-off),
[billing flow](../architecture/flows/billing.md), the sub-$10 note in the
[payments plan](../plans/2026-11-07-payments.md) and [STATUS](../STATUS.md).

## Findings

Severity: **Critical** blocks taking money now; **High** breaks something real or must be done before live; **Medium**
costs money, trust or support time; **Low** is hygiene. "Doc" in the Fix column means fixed in this PR; "Config" is a
Paddle dashboard step for the owner; "F*n*" is a code follow-up below.

## How we missed it

1. **The setup guide was written from our code's needs, not from Paddle's checklist.** It listed what the app reads
   (six variables and a webhook) and skipped account settings the code never touches. Paddle's
   [go-live checklist](https://developer.paddle.com/build/go-live-checklist) names the default payment link in its
   very first build step, and it was never read during the integration.
2. **The check didn't run the real path.** `POST /transactions/preview` validates prices and tax but needs no default
   payment link, customer or domain. The sandbox needs a default link too, so one click on Upgrade in the sandbox would
   have shown the error before production did.
3. **Tests mock Paddle.** `paddle.test.ts` and the integration tests stub `fetch`, so they prove our side of the
   contract, not Paddle's.
4. **Facts came from memory and from a provider-choice plan.** The payments plan compared providers; nobody turned
   "how does Paddle expect to be set up" into a source-linked checklist. Its sub-$10 quote had also gone stale.
5. **The error was opaque.** Our log kept `http-400`, not Paddle's code, so the cause had to be found by hand (F2).

**Process from now on:**

- For any external provider, start the setup doc from the provider's own go-live checklist, with a link per step and the
  date it was checked. Put dashboard settings in the doc even when no code reads them.
- "Verified" means the real user path ran in the sandbox: click the button, pay with a test card, see the webhook and
  the plan change. Previews, mocks and type checks don't count. Record the date and what was run.
- Log the provider's error code with every failed call.
- Re-read the provider's pricing and checklist before go-live, since both change.

**Go-live checklist (Paddle):** the [account settings](../production-environment.md#paddle-account-settings) in live
(default payment link, tax exclusive, USD balance, conversion decision, payment methods, product `saas` with 9.00 and
90.00 USD, quantity 1, key permissions and a one-year expiry, `api_key.expiring` email destination, Retain window and
discount-only cancellation flows), account verification and payouts, approval of `receipt-ocr.bhimraj.com.np`, the live
webhook destination, F1 shipped and the default link pointed at it, Vercel values and a redeploy, then one live
checkout with a 100% discount, a cancel, and the discount archived ([10c](../production-environment.md#10c-switch-from-sandbox-to-live)).

- [Paddle MCP server](https://developer.paddle.com/sdks/ai/paddle-mcp): `https://sandbox-mcp.paddle.com/mcp` (sandbox API
  key) and `https://mcp.paddle.com/mcp` (OAuth, read access until granted write). It acts on the account, so treat it
  like a key.
- [Agent skills](https://developer.paddle.com/sdks/ai/agent-skills) and a Claude Code plugin (`paddle@claude-community`
  from the `anthropics/claude-plugins-community` marketplace), plus guides for Claude Code, Cursor, Codex and Gemini
  CLI under [Build with AI tools](https://developer.paddle.com/get-started/ai).
- The [go-live checklist](https://developer.paddle.com/build/go-live-checklist) has a copy-paste agent prompt per step,
  and the [Next.js starter kit](https://developer.paddle.com/get-started/starter-kits/nextjs-saas) shows Paddle's
  reference shape (localized pricing page, inline checkout, Supabase).
