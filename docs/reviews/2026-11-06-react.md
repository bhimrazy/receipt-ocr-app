Scope: apps/web/app/app/**, app/admin/**, apps/web/components/** (not marketing, not (lab)), packages/ui.
Method: read the live code against vercel-react-best-practices and vercel-composition-patterns. react-doctor
(`npx react-doctor@latest`) was NOT run: it fetches and executes a remote package, which the dependency policy asks
you to approve first. `bunx eslint` on the two files you named was run (read-only).
Stack: Next 16.4.3, React 19.3.1, no React Compiler configured (no `reactCompiler` in next.config), lucide named

## P1: do these first

### 1. Three client-side auth fetches on every /app page, rendered twice (waterfall + layout shift)
- apps/web/components/workspace-switcher.tsx:56-58 calls `authClient.useListOrganizations()`,
  `useActiveOrganization()` and `useSession()`.
- apps/web/components/impersonation-banner.tsx:15 calls `authClient.useSession()` just to read
  `session.impersonatedBy`.
- apps/web/app/app/layout.tsx:48,63,80 mounts the switcher twice (sidebar and phone header, one hidden by CSS), and
  the banner at :53.
- The layout already has the session and scope on the server (`requireSession`, `getActiveScope`). So the browser
  does get-session + list-organizations + get-full-organization after hydration, and the switcher shows a pulse
  skeleton (workspace-switcher.tsx:69-76) on every full load and after every `router.refresh()`.
- Fix: resolve on the server and pass props.
  - Banner: `{session.session.impersonatedBy ? <ImpersonationBanner email={session.user.email} /> : null}` in the
    layout. The component then needs no client session hook at all (it still needs "use client" for the button, or
    use a `<form action={stopImpersonatingAction}>` and drop it to a server component).
  - Switcher: layout fetches the org list once (`auth.api.listOrganizations({ headers })` or a core query already
    cached with `cache()`), passes `{ organizations, activeId, canCreate }`. Keep authClient only for the mutations
    (`setActive`, `create`) followed by `router.refresh()`. Render the switcher once and let CSS place it, or
    accept two instances now that they carry no fetches.
- Same pattern in apps/web/components/account-settings.tsx:225 (`useSession` to get name/email that
  app/app/settings/page.tsx can pass as props; removes a loading skeleton) and members already do this right.
- Effort: M (half a day). Biggest user-visible win: no skeleton flash, 3 fewer requests per navigation.

### 2. `getUsageSummary()` runs twice per request, un-deduplicated

### 3. No streaming for /app: zero `loading.tsx`, zero `<Suspense>` outside admin
- `find app -name loading.tsx` finds only app/admin/loading.tsx. app/app/** blocks on the slowest query before
  painting anything; navigation between Home / History / Receipt shows the old page until the new one is fully
  ready.
- Home (app/app/page.tsx:168-216) awaits usage + counts + recent together, then renders. The upload panel needs only
  `usage`; "To check" needs `counts`; "Recent" needs `recent`.
- Fix:
  1. Add app/app/loading.tsx (skeleton like admin's) so navigations are instant.
  2. Split Home into async server components and stream:
     ```tsx
     export default function HomePage() {
       return (<>
         <PageHeader .../>
         <div className="grid ...">
           <section><Suspense fallback={<UploadSkeleton/>}><UploadSection/></Suspense></section>
           <Suspense fallback={<Skeleton className="h-48"/>}><CheckSection/></Suspense>
         </div>
         <Suspense fallback={<RecentSkeleton/>}><RecentSection/></Suspense>
       </>);
     }
     ```
     Each section awaits only its own data. `firstRun` (from counts) gates the header title and the HowItWorks card, so
     keep a cheap `counts` await at the top or render the title generically; with `cache()` on the three loaders the
     sections can share without refetching.
  3. History (app/app/history/page.tsx:27): `HistoryToolbar` needs only `filters`, so render it outside the Suspense
     and wrap only the results, so typing in the search box never blanks the toolbar and gets a skeleton for rows.
     Note the toolbar uses `useSearchParams()` in a client component: Next wants a Suspense boundary above it when
     the route is statically prerendered; here it is dynamic so it works, but add the boundary anyway.
- Effort: M. Also fixes the perceived slowness of `router.refresh()` flows (poller, role change).

### 4. ConfirmDialog: setState in effect (the lint warning), and a state-reset design that fights the parent
- packages/ui/src/components/confirm-dialog.tsx:59-65 resets `typed/error/pending` in an effect on `!open` (this is
  the only warning eslint reports on the two files; see item 8 for upload-panel).
- Best fix: move the resettable state into a child that only exists while the dialog is open. Base UI unmounts popup
  content on close, so state resets for free, no effect, no flag:
  ```tsx
  function ConfirmDialog({ open, onOpenChange, confirmText, ...rest }: ConfirmDialogProps) {
    const cancelRef = React.useRef<HTMLButtonElement>(null);
    const inputRef = React.useRef<HTMLInputElement>(null);
    const [pending, setPending] = React.useState(false); // needed by onOpenChange guard
    return (
      <AlertDialog open={open} onOpenChange={(next) => !pending && onOpenChange(next)}>
        <AlertDialogContent initialFocus={confirmText !== undefined ? inputRef : cancelRef}>
          <ConfirmBody {...rest} confirmText={confirmText} cancelRef={cancelRef} inputRef={inputRef}
                       onPendingChange={setPending} onDone={() => onOpenChange(false)} />
        </AlertDialogContent>
      </AlertDialog>
    );
  }
  ```
  `ConfirmBody` owns `typed` and `error` (and `pending`, reporting it up). If Base UI keeps content mounted for
  exit animation, key the body: `<ConfirmBody key={String(open)} .../>`.
  Simplest alternative (2 lines, same behaviour as admin/reason-dialog.tsx:53-60, which already does this
  correctly): reset inside a wrapped `onOpenChange` handler and after a successful confirm. This misses the case
  where the parent closes it programmatically, so prefer the keyed-body approach.
- Also in this package: the parent pattern `confirm` + `confirmOpen` two-state in members-table.tsx:41-48,
  receipt-actions, user-actions.tsx:96-97,221-222 exists so the dialog text survives the close animation. It is
  duplicated 4 times; see item 9.
- Effort: S.

## P2: worth doing

### 5. Upload panel: one 500-line component with 8 state hooks and avoidable churn
apps/web/components/upload-panel.tsx
- :74-77 `queueRef` mirrors `queue` through an effect (state -> ref sync) so `addFiles` can read the latest queue
  after an `await`. Replace by reading inside the functional update, which is what :133-136 already half does:
  ```ts
  setQueue((current) => {
    const room = Math.max(0, MAX_FILES - current.length);
    release(accepted.slice(room));          // side effect in updater: move out, see below
    return [...current, ...accepted.slice(0, room)];
  });
  ```
  Side effects (revokeObjectURL) in an updater are impure in StrictMode (double invoke). Cleaner: compute
  `const room` from a ref updated in the handlers that change the queue (`queueRef.current = next` inside
  `setQueueAndRef`), or keep the queue in `useReducer` with actions `add | remove | clear | mark`, and revoke URLs in
  the event handler that dispatches. The reducer also collapses `mark`/`remove`/`clear` and the three message states.
- :56-63 `busy`, `preparing`, `dragging`, `error`, `notice`, `success`: `error/notice/success` are mutually
  exclusive and always set/cleared together (:112-114, :153,:160,:192). Use one `feedback: {kind, text} | null`
  (or derive). Fewer setStates per action, no stale combination.
- :113-135 `addFiles` awaits `prepareFile` one file at a time. For 20 phone photos (canvas resize + JPEG encode)
  that is serial. Run 2-3 in parallel with a small pool; do not use unbounded `Promise.all` (decoded 12 MP bitmaps
  are ~48 MB each on mobile). `async-parallel`.
- :40 `postReceipt` and the `fetch` flow could use a form `action`/`useActionState`, but the per-file progress,
  sequencing (burst limit) and `router.push` make the current explicit loop the right tool. Leave it.
- Lint note: eslint reports no setState-in-effect warning for upload-panel.tsx on current main (only
  confirm-dialog). The only effects there are the ref-mirror (:74) and the unmount cleanup (:79-83); neither sets
  state. If CI still shows one, it is the ref-mirror pattern flagged as "update ref in effect"; the reducer/ref
  approach above removes it.
- Split suggestion for readability (composition, no perf cost): `<DropZone>` (card + inputs + drag state, which
  re-renders on every dragover only itself), `<QueueList>` (items), `<QueueFooter>` (busy/single/overLimit label
  and button). `dragging` state currently re-renders the entire panel including the list.
- Effort: M.

### 6. Date/number formatters re-created on every call
- apps/web/lib/format.ts:14,56,69,83: `new Intl.NumberFormat/DateTimeFormat` per call. History renders every row
  twice (list for <lg and table for lg+, history-results.tsx:94-98), so ~50 formatter constructions per page.
  Intl constructors are slow (tens of microseconds to ms). Hoist the date ones to module constants and memoise
  `currencyFormatter` in a `Map<string, Intl.NumberFormat | null>` (`js-cache-function-results`).
- Effort: XS.

### 8. Processing pollers: correct, small improvements
apps/web/components/processing-poller.tsx
- `ProcessingPoller` is well built (backoff, give-up, cleanup, cancelled flag). Gaps:
  - Keeps polling while the tab is hidden. Add a `document.visibilityState` check (skip tick, or pause and resume on
    `visibilitychange`). Saves requests for users with background tabs.
  - `ListPoller` calls `router.refresh()` unconditionally, which re-runs the whole /app layout (auth, scope, plan,
    usage, allowance queries) every 2-15 s for up to 3 minutes per open tab. That is the heaviest steady-state load
    in the app. Prefer a lightweight status poll like `ProcessingPoller` does, and `router.refresh()` only when a
    count changes (an endpoint returning `{inFlight}` for the workspace), or at least pause when hidden.
  - Two duplicated backoff formulas (:51 and :100); extract `nextDelay(attempt)`.
  - `gaveUp` state set inside the async `tick` is fine (not synchronous in effect).
- Effort: S.

### 9. Duplicated "pending confirm + open" pattern, and boolean prop growth
- members-table.tsx:41-48,82-106,186, receipt-actions.tsx:56,76-85, user-actions.tsx:96-97,221-225 and
  account-settings each hold `confirm` + `open` and rebuild ConfirmDialog props. Extract a hook that owns this:
  ```tsx
  const { ask, dialog } = useConfirm();     // ask({title, description, confirmLabel, destructive, onConfirm})
  ...
  return <>{...}{dialog}</>;
  ```
  The hook keeps the last config while the exit animation plays. Removes ~15 lines per call site and the
  `confirmProps` IIFE in members-table.
- ConfirmDialog props (`destructive`, `confirmText`, `cancelLabel`) are acceptable booleans-as-config for a leaf
  component. Where composition would help more: `ConfirmDialog` and `ReasonDialog` (admin/reason-dialog.tsx) are two
  forks of the same pending/error/submit state machine with different bodies. Make one `ActionDialog` shell
  (title, description, footer, pending/error handling via context or a render slot `children`) and let "type to
  confirm" and "write a reason" be body components. `ReasonDialog` already uses `children` for extra fields, which
  is the right direction. Effort: M.
- `RoleSelect` (members/role-select.tsx:32-44) is fine. `useCopyLink` living in a component file next to
  `inviteUrl` (which touches `window`) is slightly misplaced; move to `members/use-copy-link.ts`. XS.
- `UserMenu variant="avatar" | "row"` (user-menu.tsx) is an explicit-variant-by-prop; acceptable, but two exported
  `UserMenuRow` / `UserMenuAvatar` wrappers (`patterns-explicit-variants`) would read better. XS.

### 10. React 19 form APIs: where they simplify
- Admin forms (admin/settings/plan-limits-form.tsx:55-78, ocr-chain-form.tsx, user-actions, workspace-actions) hand-roll
  `pending` + `error` + `setPending(false)` around server actions. `useActionState` removes both flags:
  ```tsx
  const [state, formAction, pending] = useActionState(async (_prev, formData: FormData) => {
    const result = await savePlansAction(parse(formData));
    return result.ok ? { ok: true } : { error: result.error };
  }, {});
  <form action={formAction}> ... <Button disabled={pending}> ...
  ```
  Bonus: progressive enhancement and automatic form reset semantics. `dirty` computed via two `JSON.stringify`s per
  render (:55-56) is fine at this size but could be derived once with `useMemo` only if the form grows.
- `useOptimistic` fits the members role change (members-table.tsx:50-61): show the new role immediately, roll back on
  error, drop `busyMemberId`. Optional.
- `use()` is not needed: no client component reads a promise. Do not add it for its own sake.
- `useFormStatus` for submit buttons (`Loader2` + `disabled`) repeated in 8+ places; a shared `<SubmitButton>` in
  packages/ui would remove the prop plumbing. S.

## P3: nits

- Memoisation: nothing is memoised and nothing needs it. No `React.memo`/`useMemo`/`useCallback` anywhere in scope
  besides support-widget `useCallback`s (needed for effect deps) and ReceiptEditor `useState(() => ...)` for
  categories (fine). With 20-row lists and server-rendered pages, adding memo would be pointless. If you adopt the
  React Compiler later, the manual effect/ref patterns above are what it would flag. Not recommended now.
- history-toolbar.tsx:70-86 debounce effect with `eslint-disable react-hooks/exhaustive-deps`: reads `pathname` and
  `router` from closure. It works because it only depends on `query`. Cleaner: debounce in the `onChange` handler (set
  timer there, no effect), which also removes the disable comment and the `scheduledQ` guard logic. Alternatively
  `useDeferredValue(query)`. S.
- history-toolbar.tsx:45-51 adjust-state-during-render is the right React pattern. Keep.
- history-toolbar.tsx:58-67 `apply` and :73-82 duplicate URL building; one `pushParams(patch)` helper (also in
  admin/list-toolbar.tsx:44-53). Share a `useUrlFilters()` hook in components/. S.
- workspace-switcher.tsx:112-116 slug uses `Math.random()`; fine, server enforces uniqueness presumably.
- members-table.tsx:42 `confirmOpen` + `confirm` retained so text survives the exit animation: intentional, see #9.
- toast.tsx: `lucide-react` named imports inside packages/ui; Next's optimizePackageImports covers `lucide-react` by
  default, but packages/ui is a workspace package. Verify with `next build` output (bundle analyzer) that only used
  icons ship. If not, add `experimental.optimizePackageImports: ["lucide-react"]` (already default) or

- layout.tsx:35 `getActiveScope()` is awaited before the `Promise.all` of allowance/usage/plan. `getWorkspaceAllowance`
  and `getCurrentPlan` do not depend on scope, so start them first and await scope after:

  const [allowance, usage, {plan}] = await Promise.all([allowanceP, usageP, planP]);

  early. XS-S. This one is actually P2 on latency.

- app/app/settings/members/page.tsx:50-51 sequential `requireActiveScope` then `loadWorkspace(organizationId)`:
  dependent, fine.
- receipt/[id]/page.tsx:9 already parallel. Good.

## What is done well

- Server-first: pages are async server components; client components are leaves (toolbars, forms, dialogs, pollers).
  Marketing pages and detail pages ship almost no JS.
- Data is fetched in parallel where it matters (app/page.tsx:169, app/settings/page.tsx:26,39, receipts/[id]/page.tsx:9,
  workspaces.ts:18, admin/users page); `React.cache` on `getActiveScope` and `getCurrentPlan` dedupes per request.
- Thin props across the server/client boundary: layout passes `MenuUser`/`showAdmin` rather than the session object;
  members page maps Better Auth rows to a minimal shape.
- Derived state done right: history-toolbar.tsx:45-51 syncs the search box from the URL during render; ReasonDialog resets
  in the handler, not an effect; `url`-driven filters survive reload and back/forward.
- Effects are scoped and cleaned: ProcessingPoller (cancel flag, clearTimeout, bounded duration, backoff),
  support-widget (listener add/remove), upload-panel preview URLs revoked on unmount/remove.
- Bundle hygiene: named lucide imports, no date library (Intl with fixed locale/zone avoids hydration mismatches), no
  heavy client libs in scope, `next/image` skipped deliberately for blob previews with an eslint reason.
- Component design: packages/ui compound parts (Card*/Dialog*/AlertDialog*/Field*/Table*) are composition-first;
  PageHeader* in components/page-header follows the same style; RoleSelect and ReceiptList are focused. Accessibility
  is thoughtful (aria-live, roles, 44px targets, focus return).
- No `forwardRef` or `useContext` left to migrate (React 19 style refs as props).
