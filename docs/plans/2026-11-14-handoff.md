## Migrations

Several branches add migrations. Number them only when generating, just before merge, and regenerate on rebase so
that the snapshot `prevId` chain stays linear and the journal `when` increases (drizzle skips an older `when`
silently).

Rollout, every time:

1. Merge. The automatic production deploy skips a release that adds a migration.
2. `gh workflow run db-migrate.yml --ref main -f environment=staging-db`
3. The same with `production-db`. The owner approves it in GitHub.
4. Wait for CI on that commit.
5. `gh workflow run production.yml --ref main`
6. Check `/api/health`.

Dispatching workflows needs the `.env` `GITHUB_TOKEN`. The Codespace's own `gh` login can't dispatch or rerun jobs.

## Working on this machine

- Shared scratchpad: agents write to the same scratchpad directory. Each keeps its files in its own subdirectory,
  and checks any env or database script before running tests or dropping a database.
- Long commands (`next build`, full suites, e2e) need the Bash tool's `timeout` set to 600000 or a background run.
  The 2-minute default kills them with exit 143.
- Codespace only, not the repo: `~/.bunfig.toml` puts Bun's cache at `/workspaces/.bun-cache`, so worktrees
  hardlink packages. On a fresh machine either repeat it or ignore it.
- `support-admin.int.test.ts` "lists newest first" flakes in CI under Postgres 17. An empty commit reruns the job.
  The cause isn't known yet.
